## 05 / THE RESEARCH × ENGINEERING METHOD

<div align="center">
  <h3>QUESTION → BASELINE → BUILD → EVALUATE → SHARE</h3>
  <p><b>A repeatable way of thinking, not a claim that every project already follows this process.</b></p>
  <p>
    <img src="https://img.shields.io/badge/01-QUESTION-6D28D9?style=for-the-badge" alt="Stage 1: Question" />
    <img src="https://img.shields.io/badge/02-BASELINE-2563EB?style=for-the-badge" alt="Stage 2: Baseline" />
    <img src="https://img.shields.io/badge/03-BUILD-0891B2?style=for-the-badge" alt="Stage 3: Build" />
    <img src="https://img.shields.io/badge/04-EVALUATE-0F766E?style=for-the-badge" alt="Stage 4: Evaluate" />
    <img src="https://img.shields.io/badge/05-SHARE-B45309?style=for-the-badge" alt="Stage 5: Share" />
  </p>
</div>

| Phase | Guiding question | What I aim to produce |
| :--- | :--- | :--- |
| **01 · Question** | What problem is worth solving? | A precise problem statement and explicit assumptions. |
| **02 · Baseline** | What existing approach should I compare against? | Evidence, alternatives, and a justified reference point. |
| **03 · Build** | What is the simplest maintainable implementation? | A working prototype with clear boundaries and documentation. |
| **04 · Evaluate** | Which tests could disprove my assumptions? | Meaningful test results, failure analysis, and limitations. |
| **05 · Share** | Could someone understand or reproduce the work? | Source code, setup instructions, and an honest technical summary. |

> **My engineering principle:** A strong demo shows what works. A credible engineering report also explains what fails, why decisions were made, and what evidence supports them.
